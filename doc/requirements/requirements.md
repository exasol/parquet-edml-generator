# System Requirements

## Introduction

Parquet EDML Generator is a command-line tool that creates an EDML mapping definition for a Parquet file. Users provide the file path and receive the generated definition as command output. The project distributes native executables for Windows and Linux and provides a Java JAR for other operating systems.

## Goals

Generate an EDML definition from a Parquet file without manually writing the mapping.

## Terms and Abbreviations

###### EDML

Exasol Data Modeling Language, the serialized mapping definition generated by the tool.

###### Parquet

The columnar file format consumed by the tool.

## User Roles

###### Data Engineer

A person who supplies a Parquet file and uses its generated EDML mapping definition in a downstream Exasol integration.

## Features

### Generate EDML From Parquet
`feat~generate-edml-from-parquet~1`

The tool converts the schema of a Parquet file into an EDML mapping definition that users can use with Exasol integrations.

Needs: req

## User Requirements

The following requirements refine the product feature into user-visible behavior. Requirements about detailed type conversion and error reporting are inferred from implementation and tests because the README does not specify those contracts.

### Accept a Parquet File Path
`req~accept-parquet-file-path~1`

The command-line application accepts a path to the Parquet file whose schema it maps.

Rationale:

Users need to select the exact local file whose schema they want to use as the basis for an EDML definition.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Run From a Documented Distribution
`req~run-from-documented-distribution~1`

Users can run PEG from a Java JAR with Java 21 or later, or from a self-contained native executable for Linux or Windows.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Emit a Serialized EDML Definition
`req~emit-edml-definition~1`

For a readable Parquet file with supported schema types, the application writes a serialized EDML mapping definition to standard output and exits successfully.

Rationale:

Users need a definition they can capture and pass to an Exasol integration without manually transcribing the file schema.

Status: draft

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Map Primitive Parquet Fields
`req~map-primitive-parquet-fields~1`

The generated definition represents each supported primitive Parquet field as an EDML mapping.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Map Logical Parquet Fields
`req~map-logical-parquet-fields~1`

The generated definition represents each supported logical Parquet field as an EDML mapping.

Rationale:

Users need semantic values such as dates, timestamps, and decimals to retain their meaning.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Preserve Nested Parquet Fields
`req~preserve-nested-parquet-fields~1`

The generated definition preserves the structure of supported nested Parquet fields.

Rationale:

Users need data from complex Parquet records to remain available when they generate a definition.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Normalize Destination Field Names
`req~normalize-destination-field-names~1`

The generated definition uses upper snake case for each destination field name.

Rationale:

The naming convention keeps the generated EDML definitions consistent across files.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

### Report Unsupported Input
`req~report-unsupported-parquet-types~1`

When the Parquet schema contains an unsupported type, the application reports the type and column in an error instead of emitting a successful mapping definition.

Rationale:

Users need to identify the incompatible field and type so they can correct the input or request support. Incomplete mapping would lead to hard-to-trace errors.

Covers:
- `feat~generate-edml-from-parquet~1`

Needs: scn

## Acceptance Scenarios

### Generate a Definition From a Parquet File
`scn~generate-definition-from-file~1`

**Given** a readable Parquet file with supported schema types
**When** the user runs the application with that file path
**Then** the application writes a parseable EDML definition to standard output
**And** exits with status zero.

Covers:
- `req~accept-parquet-file-path~1`
- `req~emit-edml-definition~1`

Needs: dsn

### Run From a Documented Distribution
`scn~run-from-documented-distribution~1`

**Given** Java 21 or later is available, or the user is running Linux or Windows
**When** the user starts the corresponding PEG release artifact
**Then** PEG starts without requiring an additional runtime for the native executable.

Covers:
- `req~run-from-documented-distribution~1`

Needs: dsn

### Convert Primitive Schema Fields
`scn~convert-primitive-schema-fields~1`

**Given** a Parquet file containing supported primitive fields
**When** the application generates its definition
**Then** the EDML definition contains the corresponding field mappings.

Covers:
- `req~map-primitive-parquet-fields~1`

Needs: dsn

### Convert Logical Schema Fields
`scn~convert-logical-schema-fields~1`

**Given** a Parquet file containing supported logical fields
**When** the application generates its definition
**Then** the EDML definition contains the corresponding field mappings.

Covers:
- `req~map-logical-parquet-fields~1`

Needs: dsn

### Preserve Nested Schema Fields
`scn~preserve-nested-schema-fields~1`

**Given** a Parquet file containing supported nested fields
**When** the application generates its definition
**Then** the EDML definition preserves the nested field structure.

Covers:
- `req~preserve-nested-parquet-fields~1`

Needs: dsn

### Normalize Destination Field Names
`scn~normalize-destination-field-names~1`

**Given** a Parquet file containing fields with non-upper-snake-case names
**When** the application generates its definition
**Then** every destination field name uses upper snake case.

Covers:
- `req~normalize-destination-field-names~1`

Needs: dsn

### Reject an Unsupported Schema Type
`scn~reject-unsupported-schema-type~1`

**Given** a Parquet file whose schema contains a type the converter does not support
**When** the application generates its definition
**Then** it reports the unsupported type and column
**And** does not return a successful definition.

Covers:
- `req~report-unsupported-parquet-types~1`

Needs: dsn
